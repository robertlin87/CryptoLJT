- 故障与修复：两个旧 SSH 窗口残留的前台进程（PID 5188 / 5298，命令行是**相对路径** `.venv/bin/python scripts/run.py`）持有 telethon session sqlite 锁，systemd 启动报 `sqlite3.OperationalError: database is locked` 并循环重启。`pkill -f '^/opt/autotrade/.venv/bin/python'` 匹配不到相对路径进程，必须按 PID kill -9 或用 `pkill -9 -f '^\.venv/bin/python scripts/run\.py'`，清干净后服务正常，最终只剩 PID 5605（PPID 1）。
- 操作规矩：以后重启只用 `systemctl restart autotrade`，**不要再手动跑 `scripts/run.py`**，否则再次抢 session 锁。查日志 `journalctl -u autotrade --no-pager -n 15`。

## 软件界面架构（读码结论，供后续改动参考）

- 两套界面并存且互不复用入口：① CLI：`install.bat` / `start_run.bat` → `scripts/run.py` → `cli_setup.py`（首次向导 + 启动选单 1 改 TG / 2 改交易所 / 3 改风险乘数 / 4 改 TP 比例 / 回车监听），VPS systemd 也走这条；② GUI：`run_app.py` → `app.main()` → `gui/wizard.py`（Tkinter 四页 Notebook：欢迎 / Telegram / 交易所 / 完成）+ `gui/runner.py`（运行日志窗，按钮「重新設定」「匯出問題報告」），`autotrade.spec` 打包的是这条且 `console=False`。`wizard.py` 只是 GUI 向导的薄封装。
- `gui/dialogs.py` 的 `GuiPrompter` 用队列把 TG 手机号/验证码/2FA 弹窗从后台 asyncio 线程转交主线程，`_poll_prompt` 每 100ms 轮询一次、每次只处理一个请求；取消弹窗返回空串，没有真正的取消机制。
- 文档冲突：README 只描述 CLI 且写「全程不彈窗」，与 exe 的 GUI 不符；README 引用的 `docs/HANDOFF.md` 不存在（docs 下只有 PLAN.md）。
- GUI 已知缺口：`gui/wizard.py` 的 `int(api_id)` 未捕获非数字输入（189、290 行）；「儲存並自檢」按钮无禁用/进度态，重复点击会并发跑 Telethon 登录抢 session 锁；`runner.py:85` 的「重新設定」只删 config.yaml、不删 TG session（CLI 的 `_remove_session` 有处理），换账号会残留旧 auth_key；运行窗无停止按钮，关窗即靠进程退出终止 daemon 线程，Telethon 未显式 disconnect；GUI 没有 CLI 那套 1/2/3/4 单项修改选单。
